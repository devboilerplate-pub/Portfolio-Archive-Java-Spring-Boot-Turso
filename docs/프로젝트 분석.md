# 프로젝트 분석: Portfolio Project Archive

## 1. 프로젝트 개요
- **주제**: Creative Technical Archive를 주제로 한 포트폴리오 관리 프로젝트
- **기술 스택**: Java 17+ (Java 17 / 21 LTS 호환), Spring Boot 3.4.4, Turso DB (libSQL)
- **빌드 도구**: Gradle
- **아키텍처 특징**:
  - React, Vue 등의 별도 프론트엔드 프레임워크나 JPA/Hibernate 같은 ORM을 배제함.
  - `Controller → Service → Repository → Turso HTTP SQL`로 이어지는 직관적이고 가벼운 아키텍처 흐름을 차용함.

## 2. 프로젝트 주요 구조
- `src/main/java/com/example/archive/`
  - `controller`: 클라이언트의 HTTP 요청(API 및 뷰)을 처리
  - `service`: 애플리케이션의 비즈니스 로직과 유즈케이스 조정
  - `repository`: 순수 SQL을 작성하고 Turso DB와의 연결 및 데이터 처리를 담당
  - `model`, `dto`: 데이터 모델 및 전송 객체
- `src/main/resources/`
  - `application.properties`: 애플리케이션 구동 포트(8080) 및 Turso 환경변수 매핑 설정
  - `static` / `templates`: Spring Boot 환경에서 제공하는 최소한의 HTML/CSS/JavaScript 리소스

## 3. 데이터베이스 구성 및 실행 모드 (Turso 연결 vs 임시 목업 모드)

### 3.1. Turso 연결 필수 여부
> **결론**: **Turso DB 연결 없이도 즉시 실행 가능하며, 임시 목업(인메모리 프리뷰 모드) 상태로 100% 정상 동작합니다.**
> 
> 별도의 클라우드 DB 가입, 스키마 세팅, 환경 변수 주입 과정 없이도 프로젝트를 로컬에서 즉시 구동하여 모든 기능을 온전히 테스트할 수 있습니다.

### 3.2. Dual-Mode 아키텍처 동작 원리
`ProjectRepository.java` 내부에는 환경 변수 설정 여부에 따라 시스템의 데이터 저장소를 자동으로 전환하는 **Dual-Mode** 분기 로직이 구현되어 있습니다:

```java
public boolean isTursoConfigured() {
    return !dbUrl.isBlank() && !token.isBlank();
}
```

1. **환경 변수가 없을 때 (기본 상태 - 로컬 임시 목업 모드)**:
   - **시드(Seed) 데이터 자동 적재**: 애플리케이션 시작 시 8개의 완성도 높은 포트폴리오 프로젝트 데이터가 메모리(`ConcurrentHashMap`)에 자동으로 초기화됩니다.
   - **완전한 CRUD 지원**: 단순 조회를 넘어 **새 프로젝트 등록(Create), 단건/전체 조회(Read), 수정(Update), 삭제(Delete)** 등 모든 동작이 메모리 상에서 실시간으로 완벽하게 동작합니다.
   - **상태 확인 엔드포인트**: `GET /api/status` 호출 시 데이터베이스 연결 상태가 `"PREVIEW MEMORY SEED"`로 명확하게 표시됩니다.
   - **특징 및 유의사항**: 영구 디스크 저장이 아닌 인메모리 방식이므로, 서버 애플리케이션을 종료하고 재시작하면 기본 8개 시드 데이터 상태로 리셋됩니다. 로컬 기능 시연, 디자인 확인, UI/UX 개발에 매우 적합합니다.

2. **환경 변수가 있을 때 (운영/영구 저장 모드)**:
   - `TURSO_DATABASE_URL`과 `TURSO_AUTH_TOKEN`이 모두 설정되어 있는 경우 동작합니다.
   - Turso 원격 클라우드 DB와 HTTP Pipeline v2 프로토콜을 통해 안전하게 통신하며, 모든 C/U/D 및 조회가 원격 데이터베이스에 영구적으로 반영됩니다.
   - **초기 생성 테이블 스키마**:
     ```sql
     CREATE TABLE IF NOT EXISTS projects (id INTEGER PRIMARY KEY AUTOINCREMENT, title TEXT NOT NULL, category TEXT NOT NULL, description TEXT, problem TEXT, solution TEXT, technology TEXT, image TEXT, github_url TEXT, demo_url TEXT, created_at TEXT);
     CREATE TABLE IF NOT EXISTS categories (id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL UNIQUE);
     ```

### 3.3. 목업 모드로 즉시 실행 및 테스트하는 방법
어떠한 환경 변수도 설정하지 않은 상태에서 터미널에 다음 명령어를 입력하면 즉시 로컬 목업 모드로 구동됩니다:

```powershell
.\gradlew.bat bootRun
```

실행 후 브라우저에서 `http://localhost:8080`에 접속하면 다음 모든 기능이 목업 상태에서 정상 작동합니다:
- 8개의 완성도 높은 포트폴리오 프로젝트 카드 그리드 렌더링
- 실시간 텍스트 검색 및 카테고리 필터링 드롭다운
- 상단 `+ NEW PROJECT` 버튼을 통한 신규 프로젝트 모달 팝업 등록
- 각 프로젝트 카드 클릭 시 상세 정보 모달 오픈 및 내용 수정/삭제
- 프로젝트 개수, 카테고리 개수, 기술 스택 카운트 등의 통계 지표 실시간 반영

## 4. 사전 필수 조건 (Prerequisites)

프로젝트를 실행하기 전에 다음 조건이 시스템에 전역적으로 구성되어 있어야 합니다. (Windows 기준)

### 4.1. JDK 21 설치 및 환경 변수 설정
본 프로젝트는 Java 21 버전을 기반으로 동작합니다.

1. **JDK 21 다운로드 및 설치**:
   - Oracle JDK, OpenJDK, Amazon Corretto, Azul Zulu 등에서 제공하는 JDK 21 버전을 다운로드하여 설치합니다.
   - 예: [Amazon Corretto 21 다운로드 페이지](https://aws.amazon.com/ko/corretto/)에서 Windows x64 MSI 설치 파일을 다운로드하여 기본 경로로 설치를 진행합니다.

2. **JAVA_HOME 환경 변수 설정**:
   - `Windows 키`를 누르고 `시스템 환경 변수 편집`을 검색하여 실행합니다.
   - `고급` 탭의 하단에 있는 `환경 변수(N)...` 버튼을 클릭합니다.
   - 하단의 **시스템 변수(S)** 영역에서 `새로 만들기(W)...`를 클릭합니다.
     - **변수 이름(N)**: `JAVA_HOME`
     - **변수 값(V)**: 실제 JDK가 설치된 경로를 입력합니다. (예: `C:\Program Files\Amazon Corretto\jdk21.0.x_x` 또는 `C:\Program Files\Java\jdk-21`)
     - 입력 후 `확인`을 클릭합니다.

3. **PATH 환경 변수 등록**:
   - 동일한 **시스템 변수(S)** 영역에서 `Path` 변수를 찾아 선택한 뒤 `편집(I)...`을 클릭합니다.
   - 우측의 `새로 만들기(N)`를 클릭하고 `%JAVA_HOME%\bin`을 입력합니다.
   - 적용 우선순위를 높이기 위해 `위로 이동(U)` 버튼을 눌러 목록 상단에 배치한 뒤, `확인`을 눌러 모든 창을 저장하고 닫습니다.

4. **전역 설정 확인**:
   - 완전히 새로운 명령 프롬프트(CMD)나 PowerShell 창을 열어 아래 명령어를 차례로 입력합니다.
   ```powershell
   java -version
   javac -version
   ```
   > 💡 **참고**: 터미널에 `openjdk version "21.x.x"`와 같은 결과가 정상적으로 출력되어야 합니다.

## 5. 프로젝트 실행 및 종료 가이드

해당 프로젝트의 구동 및 종료 프로세스는 다음과 같습니다 (Windows 기준).

### 실행 방법

1. **환경 변수 설정**: 터미널(PowerShell 등)을 열고 DB 접속에 필요한 인증 정보를 환경 변수로 주입합니다.
   ```powershell
   # PowerShell 기준 환경변수 설정
   $env:TURSO_DATABASE_URL="libsql://your-db-your-org.turso.io"
   $env:TURSO_AUTH_TOKEN="your-token"
   ```
   > ⚠️ **주의**: 운영 환경에서는 이 정보를 소스 코드나 파일에 기록하지 말고 보안 Secret을 통해 주입해야 합니다.

2. **애플리케이션 구동**: 프로젝트 루트 경로에서 Gradle Wrapper를 통해 애플리케이션을 실행합니다.
   ```powershell
   .\gradlew.bat bootRun
   ```

3. **웹 접속 확인**: 로컬 서버 구동이 완료되면, 브라우저를 열어 `http://localhost:8080`에 접속하여 서비스가 정상적으로 표시되는지 확인합니다. (API는 `/api/projects`, `/api/categories` 등의 경로로 접근)

### 종료 방법

1. **프로세스 중지**: 애플리케이션이 실행 중인 터미널 창(콘솔)을 클릭하고 `Ctrl + C` 키를 입력합니다.
2. **배치 작업 종료**: 프롬프트 창에 `일괄 작업을 끝내시겠습니까 (Y/N)?` 메시지가 나타나면 `Y`를 누르고 `Enter`를 입력하여 서버와 Gradle 프로세스를 완전히 종료합니다.

## 6. 보안 및 아키텍처 개선 사항 (Refactoring)
- **SQL Injection 방어**:
  - `ProjectRepository`에서 문자열 병합 방식을 제거하고 Turso libSQL v2 pipeline의 `args` 파라미터 바인딩(`type`, `value`) 방식을 적용하여 원천 방어 완료.
- **요청 데이터 유효성 검증(Validation)**:
  - `ProjectRequest` DTO에 `@NotBlank`, `@Size` 검증 추가 및 `ProjectController`에 `@Valid` 적용.
- **예외 처리 및 HTTP 응답 표준화**:
  - 엔티티 미존재 시 `404 Not Found`를 반환하도록 `ProjectNotFoundException` 및 전역 에러 처리기(`GlobalExceptionHandler`) 도입.
- **단건 조회 성능 최적화**:
  - 전체 조회 후 필터링하던 비효율적인 구조를 `SELECT ... WHERE id = ?` 개별 조회로 전환.
- **Gradle Wrapper 완비**:
  - 프로젝트 루트에 누락되었던 `gradlew.bat` 및 Wrapper 설정 생성 완료.

## 7. 프로젝트 GitHub 배포 및 협업 가이드

본 프로젝트를 깃허브(GitHub)에 업로드하고, 다른 컴퓨터에서 클론(Clone)하여 실행하는 전체 과정입니다.

### 7.1. 현재 프로젝트를 GitHub에 업로드하기 (현재 컴퓨터)

#### 1. GitHub에서 새 리포지토리 만들기
1. GitHub 웹사이트에 접속하여 로그인합니다.
2. 우측 상단의 `+` 아이콘을 누르고 **[New repository]**를 클릭합니다.
3. **Repository name**(저장소 이름)을 입력합니다. (예: `my-java-portfolio`)
4. 다른 설정(Add a README file 등)은 **아무것도 체크하지 않고**, 하단의 **[Create repository]** 버튼을 클릭합니다.
5. 화면에 나타나는 `https://github.com/아이디/이름.git` 형식의 주소를 복사해 둡니다.

#### 2. VS Code에서 코드 업로드하기
1. 현재 열려 있는 프로젝트(VS Code)에서 터미널을 엽니다. (단축키: <kbd>Ctrl</kbd> + <kbd>`</kbd>)
2. 터미널 창에 아래 명령어들을 순서대로 한 줄씩 입력하고 엔터를 칩니다.

```bash
# 1. 현재 폴더를 Git 저장소로 초기화합니다.
git init

# 2. 변경된 모든 파일을 업로드할 준비(Staging) 상태로 만듭니다. 
# (보안상 중요한 .env 파일은 .gitignore 파일에 의해 자동으로 제외됩니다)
git add .

# 3. 어떤 작업을 했는지 메모(Commit)를 남깁니다.
git commit -m "초기 프로젝트 세팅 업로드"

# 4. 기본 브랜치 이름을 master에서 main으로 변경합니다.
git branch -M main

# 5. 아까 복사해둔 깃허브 저장소 주소를 내 컴퓨터와 연결합니다. (주소를 붙여넣으세요)
git remote add origin https://github.com/본인아이디/저장소이름.git

# 6. 최종적으로 코드를 깃허브로 밀어 올립니다(Push).
git push -u origin main
```
성공적으로 완료되면 깃허브 웹사이트를 새로고침 했을 때 소스 코드가 정상적으로 업로드된 것을 확인할 수 있습니다.

### 7.2. 다른 컴퓨터에서 프로젝트 가져와서 실행하기 (새 컴퓨터)

새로운 컴퓨터에서 프로젝트를 이어서 작업하거나 실행하는 방법입니다.

#### 1. 필수 프로그램 확인
새로운 컴퓨터에는 기본적으로 다음 두 가지가 설치되어 있어야 합니다.
* **Git**: 소스 코드를 다운로드하기 위해 필요합니다.
* **Java 17 이상**: 본 프로젝트의 권장 실행 환경입니다.

#### 2. 프로젝트 다운로드 (Clone)
1. 코드를 저장하고 싶은 바탕화면이나 폴더에서 우클릭 후 **[Open in Terminal]**(터미널 열기)를 선택합니다.
2. 아래 명령어를 입력하여 프로젝트를 통째로 다운로드합니다.
```bash
git clone https://github.com/본인아이디/저장소이름.git
```
3. 다운로드가 완료되면 VS Code를 열고, 방금 다운로드된 폴더를 엽니다.

#### 3. 환경 변수(.env) 설정하기 ⚠️ (매우 중요)
GitHub에 코드를 올릴 때 보안을 위해 데이터베이스 비밀번호 등이 적힌 `.env` 파일은 업로드되지 않습니다. 새 컴퓨터에서 이를 다시 구성해야 합니다.
1. VS Code 탐색기에서 `.env.example` 파일을 엽니다.
2. 해당 파일과 동일한 위치에 새로운 파일을 만들고 이름을 `.env`로 짓습니다.
3. `.env.example`에 있는 내용을 복사해서 새 `.env` 파일에 붙여넣습니다.
4. 비워져 있는 값(예: `TURSO_DATABASE_URL` 등)에 실제 데이터베이스 접속 정보와 인증 토큰을 채워 넣고 저장합니다.

#### 4. 프로젝트 실행하기
이 프로젝트는 **Gradle**을 사용하기 때문에 새 컴퓨터에 복잡한 빌드 도구를 따로 설치할 필요 없이, 폴더 안에 내장된 실행기(`gradlew`)를 이용하면 됩니다.

VS Code 터미널을 열고 운영체제에 맞게 아래 명령어를 입력합니다.

**Windows의 경우:**
```bash
.\gradlew.bat bootRun
```

**Mac 또는 Linux의 경우:**
```bash
./gradlew bootRun
```
*(Mac에서 `Permission denied` 권한 오류가 뜬다면 `chmod +x gradlew` 를 먼저 입력한 후 다시 실행하세요.)*

#### 5. 접속 확인
터미널에 `Started [어플리케이션 이름] in ... seconds` 라는 문구가 나타나면 서버가 정상적으로 켜진 것입니다. 인터넷 브라우저를 열고 `http://localhost:8080` 으로 접속하여 프로젝트가 잘 동작하는지 확인합니다.
